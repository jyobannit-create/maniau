## 3. 既存自動化との役割分担・衝突回避

| ジョブ | 現状 | 今後 | 触るファイル |
|---|---|---|---|
| update-exams（日程更新・資格追加） | launchd 月曜 7:00・main 自動push | **ローカルのまま継続**（公式サイト多数への WebFetch が必要で、クラウドのネットワーク許可リスト管理が重いため） | `data/exams/*.json` の **日程系**（sessions/fee/lastVerified/sources 等）、`data/queue.md`、`reports/YYYY-MM-DD.md` |
| gsc-scan（GSC取得＋スキャン） | launchd 月曜 7:30 | ループ初回成功後に**停止**（ループの①に吸収） | `reports/gsc/`、`reports/seo-scan-*` |
| seo-auto（月次PR） | launchd 毎月1日 8:00 | **ループ稼働前に停止**（同じ seo フィールドを触るため） | `seo/auto-*` ブランチ |
| **seo-loop（本設計）** | — | Routine 火曜 6:00 JST | `data/exams/*.json` の **SEO系フィールドのみ**、`scripts/build.mjs`（opt-in 追加のみ）、`loop/*`、`reports/seo-annotations.ndjson` |

衝突回避ルール:
1. **曜日を分ける**：update-exams は月曜、ループは火曜（約23時間差）
2. **フィールドで分ける**：ループは日程系フィールドを編集しない／update-exams は SEO系フィールドを編集しない（`/update-exams` の禁止事項に1行追記する）
3. **push 前に `git pull --rebase`**。コンフリクトしたら自分の施策コミットを捨て、記憶ファイルだけ push して失敗通知
4. 未マージPR `seo/auto-2026-09-10` は close する（中身は既に main に反映済みか確認のうえ。判断はユーザー）

## 5. 観察期間と判定基準

GSCは再クロール3〜14日＋データ反映2〜3日のラグがあるため、**実施後7日間は判定に使わない**。

| 項目 | 定義 |
|---|---|
| 判定日 | 実施日＋21日（＝3回後の実行で判定） |
| 主指標 | **ページ全体**（匿名化クエリを含む）のクリック・表示・CTR・平均順位 |
| 対象クエリ群（参考） | 施策時に記録した表示上位クエリ（最大10件）。判定には使わず参考値として残す |
| 前期間 | 実施日−31日 〜 実施日−4日（28日。GSCの確定遅れ3日を除く） |
| 後期間 | 実施日＋7日 〜 判定日−3日（11日）。比較は**1日あたり平均**に正規化 |

| 判定 | 条件（ページ全体） | その後 |
|---|---|---|
| 達成 | CTR が前期間比 +30%以上 かつ クリック/日が増加、または 平均順位が2位以上改善 | ロック解除。handover に「効いた手」記録 |
| 継続 | 後期間の表示回数 < 50（データ不足） | **1回だけ**14日延長。再度不足なら「判定不能」で別手へ |
| 悪化 | CTR −30%以下 かつ クリック/日減少、または 平均順位が3位以上悪化 | **自動で施策前の値に戻して公開**。handover に「効かなかった手」＋恒久ルール候補 |
| 別手へ | 上記以外（変化なし） | ロック解除。次回そのページを選ぶ場合は別手法を使う |

※閾値は初期値。4週ごとに handover の成績を見て人間が見直す（§11）。

> 実装メモ（2026-10-16）: 当初は対象クエリ群で判定する設計だったが、実データで shikisai の上位10クエリの表示は28日で29件、ページ全体では254件だった（GSCはクエリの多くを匿名化する）。サンプル不足で「継続」ばかりになるため、主指標をページ全体に変更した。

## 6. 対象選定と施策の上限

### 対象選定の優先順位（上から最初に該当した1ページ）

| 順 | 条件 | 根拠データ |
|---|---|---|
| 1 | 回帰アラート（重大な順位下落）のページ | seo-scan `regressions` |
| 2 | titleLint（実測クエリの核語が title/description に無い） | seo-scan `titleLint` |
| 3 | CTR機会（順位≤10・表示多・CTRが期待値の半分未満） | seo-scan `ctrOpportunities` |
| 4 | 順位11〜20位で表示が多いページ | gsc byPage |
| 5 | コンテンツギャップ（既存ページがあるのに20位以下） | seo-scan `contentGaps` |
| 6 | 前回「別手へ」判定のページ（別の手法で再挑戦） | metrics.md 判定済み |

除外条件:
- 観察中（ロック中）のページ、`seo-annotations.ndjson` で21日以内に改修したページ
- **申込締切まで7日以内のページ**（検索ピーク中に揺らさない）
- 候補ゼロ → 何もしない（計測と答え合わせだけ記録して終了）

### 手法メニュー（1回1種類まで）

| ID | 手法 | 変更箇所 | 影響範囲 |
|---|---|---|---|
| M1 | title 改修 | `seoTitle` | 1ページ |
| M2 | description 改修 | `seoDescription` | 1ページ |
| M3 | 導入文（description本文）の補強 | `description` | 1ページ |
| M4 | FAQ節の追加 | 新フィールド `faq[]`（初回のみ build.mjs に opt-in 描画＋FAQPage構造化データを追加） | 1ページ |
| M5 | 関連資格への内部リンク | 新フィールド `relatedSlugs[]`（同上） | 1ページ |

### 1回あたりの上限
- 改善 **1ページ・1手法**
- `build.mjs` 変更は **opt-in 型のみ**（そのフィールドを持たないページの出力が1バイトも変わらないこと＝§7 の差分検査で保証）
- サイト全体に効くテンプレート変更・CSS・レイアウト・noindex・301・ハブ新設は**ループでは行わない**（因果が分からなくなるため）。必要と判断したら handover の「要人間判断」に書くだけ

## 7. 検証・公開（全自動公開の安全装置）

自動公開にする代わりに、push 前に以下を**全部**通す。1つでも落ちたら施策を破棄し、記録だけ残して失敗通知。

| # | 検証 | 方法 | 狙い |
|---|---|---|---|
| V1 | データ検証 | `node scripts/check.mjs` | 既存の日付整合性・鮮度チェック |
| V2 | 変更範囲 | `loop/scripts/verify.mjs`：施策前後で `site/` を差分し、**対象ページ（＋sitemap.xml）以外のHTMLが変わっていない**こと | 1施策1ページの保証 |
| V3 | 事実整合 | 同上：seo フィールド・FAQ に出てくる日付・年度・受験料が、同じ JSON の `sessions`/`fee` に存在すること。合格率等の数値は禁止 | 推測日付・創作数値の混入防止（データの鉄則） |
| V4 | 機械的クエリ照合 | 同上：対象クエリ群の上位核語が新 title/description に含まれること（seo-scan の titleLint ロジックを流用） | 構造チェック |
| V5 | **意味的整合（独立エージェント）** | ⑤に関与していない新規サブエージェントに「実測クエリ一覧」と「生成後の title/description/FAQ」だけを渡し、検索意図とのズレ・正式名称の欠落・誤解を招く表現を指摘させる。指摘ありなら⑤に1回だけ差し戻し、2回目も指摘なら破棄 | 2026-08-17 kangyo の教訓（shortName「管業」置換でフルネーム消失を構造チェックが見逃した） |
| V6 | 表示幅 | `seoTitle` の幅 ≤ 36（既存 seoTitle の最大 35.5 に合わせた上限。32 超は警告のみ） | 極端な長文化の防止 |

公開手順:
1. `git pull --rebase` → commit（`loop: YYYY-MM-DD {slug} {手法}`）→ `git push origin main`
2. 本番 `https://maniau-shikaku.com/exams/{slug}/` を30秒間隔・最長10分ポーリングし、新 title が出たら成功
3. 10分で反映されなければ「公開未確認」として記録・通知（ロールバックはしない。次回①で再確認）

## 10. 失敗時の挙動と通知

| 失敗箇所 | 挙動 | 通知 |
|---|---|---|
| ① GSC取得失敗 | 推測値で埋めない。答え合わせ・施策をスキップし、記録のみ | Gmail |
| ② 判定で悪化 → 自動revert | revert を公開して記録 | Gmail（悪化した施策と戻した内容） |
| ⑦ 検証 V1〜V6 不合格 | 施策を破棄（コミットしない）。記録のみ | Gmail |
| ⑦ push コンフリクト | 施策コミットを捨て、記憶ファイルだけ push | Gmail |
| ⑦ 本番反映を10分で確認できず | 記録して終了（次回①で再確認） | Gmail |
| 回帰アラート（seo-scan `hasHighRegression`） | 通常どおり優先1で対象化 | Gmail |
| 正常終了・候補ゼロ | 記録のみ | **通知しない** |

通知本文: 「どのステップで / 何が / どう失敗したか / 該当コミット・ログの場所」。送信先は Gmail コネクタの認証済みアカウント自身（リポジトリは public のためアドレスはファイルに書かない）。
